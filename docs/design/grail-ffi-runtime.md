# First Grail-facing wrappers over the C OS ABI

2026-11-08. Status: **implemented and executed on Linux x86-64**. This is the first
Grail-facing standard-library layer over `include/grail/`, using the C FFI contract in
`feature/ffi` (`extern "C"`, byte views, `CStr`, opaque handles, C-layout records and
`T |? Error`).

The C compiler/runtime in this checkout does not yet contain the FFI; the wrappers are
compiled by an FFI-capable tree compiler (`GRAIL_FFI_COMPILER`). Nothing here changes
`compiler/native.grl` or `compiler/runtime.grl`.

## Location and loading

`lib/sys/grail_ffi.grl` is module `sys_grail`. It deliberately sits in a subdirectory: the
current standard-library loader auto-includes only top-level `lib/*.grl`, so adding this
module does not affect existing programs. Pass it explicitly until the FFI compiler is the
normal compiler and the module is installed as part of the standard library.

The module declares one deduplicated link input, `grail_ffi_linux.o`, resolved relative to
`lib/sys/` by the FFI compiler. The object is **generated by the test/build script**, not
committed: it combines the Linux reference backend and `runtime/abi/ffi/grail_ffi_shim.c`.
See `.gitignore`.

## Surface

```grl
pub const OPEN_READ: u64 = 1;
pub const OPEN_WRITE: u64 = 2;
pub const OPEN_CREATE: u64 = 4;
pub const OPEN_TRUNCATE: u64 = 8;
pub const OPEN_APPEND: u64 = 16;
pub const OPEN_EXCLUSIVE: u64 = 32;
pub const CLOCK_MONOTONIC: u64 = 0;
pub const CLOCK_REALTIME: u64 = 1;

handle File;

pub enum Error { Status(i64) }

pub fn init() -> unit |? Error;
pub fn shutdown() -> unit |? Error;
pub fn open(path: &[u8], flags: u64, mode: u64) -> File |? Error;
pub fn read(file: File, buffer: &mut [u8]) -> u64 |? Error;
pub fn read_bytes(file: File, capacity: u64) -> u8[] |? Error;
pub fn write(file: File, data: &[u8]) -> u64 |? Error;
pub fn close(file: File) -> unit |? Error;
pub fn stat(file: File) -> FileStat |? Error;
pub fn size(file: File) -> u64 |? Error;
pub fn now(clock: u64) -> i64 |? Error;
pub fn monotonic() -> i64 |? Error;
pub fn wall() -> i64 |? Error;
pub fn env_get(name: &[u8], out: &mut [u8]) -> u64 |? Error;
pub fn env_get_bytes(name: &[u8], capacity: u64) -> u8[] |? Error;
pub fn env_set(name: &[u8], value: &[u8]) -> unit |? Error;
```

`FileStat` mirrors the C record exactly: `struct_size`, `abi_version`, `kind`, `flags`,
`size`, `mode`, `link_count`, `device`, `inode`, `modified_ns`, `accessed_ns`,
`created_ns` (twelve 64-bit fields, 96 bytes). The executed test checks
`struct_size == 96`, `abi_version == GRAIL_ABI_VERSION`, and `kind == FILE` so a layout
regression fails at runtime as well as at C compile time.

## Exact boundary rules

- **Paths and data** cross as `&[u8]`/`&mut [u8]` pairs `(pointer, length)`. The pointer is
  the view's own storage; there is no copy, no NUL terminator requirement and no
  `CStr` in this surface. C may read/write the bytes only for the duration of the call and
  must not retain the pointer.
- **Buffers are call-scoped loans.** `read`/`env_get` write at most the view's capacity and
  return the actual/required length. A returned length greater than the buffer capacity is
  a short read/query, not an error; `read_bytes`/`env_get_bytes` allocate a Grail-owned
  vector and copy exactly the returned prefix.
- **Short I/O is legal.** `write` returns the number of bytes written (0 or less than the
  input is valid); callers that need a full write must loop. `read` returning 0 is clean
  EOF.
- **`File` is a C-owned opaque handle.** Grail never constructs, inspects, sizes, borrows or
  frees it. Treat it as affine by convention: call `close` exactly once, never use it after
  close or double-close. The compiler's handles are not linear in this increment, so the
  convention is not machine-checked.
- **No C-owned pointer is returned.** `open` returns a handle; `stat`/`time` fill
  Grail-owned out-records; byte results are copied into Grail-owned vectors. C never hands
  back a `u8[]`/view or a pointer Grail would drop.
- **Out-records are Grail-owned.** `LengthOut`, `TimeOut` and `FileStat` are constructed by
  Grail, passed as the C record address, written by C during the call, and freed by Grail's
  normal record drop. C must not retain or free them.
- **Errors are negative statuses.** `grail_status`/`grail_result` values cross as `i64`;
  the wrapper maps negative values to `Error::Status(code)`. No `errno` is read, cleared or
  synthesized at the boundary. A caller that needs the raw OS detail can later call the
  ABI's `grail_os_error_last` through another declaration.
- **Initialization is explicit.** `init()` must run before any file/time/env call and
  `shutdown()` after all handles are closed. `grail_ffi_init` supplies a malloc/free
  allocator and an empty startup environment; the real Grail entry shim must supply the
  runtime allocator and UTF-8 argv/environment blocks when this surface is integrated.
- **The handle-return adapter is thread-local and immediate.** The C ABI writes a handle
  through an out-pointer, which the current scalar/handle FFI cannot express. The test shim
  stores it in a thread-local slot; `open` reads that slot immediately. No other open may
  intervene on the same thread, and the adapter is not part of the stable ABI.

## Build and execution

`tools/test-ffi-runtime.mjs`:

1. compiles the Linux reference backend and the FFI shim into
   `lib/sys/grail_ffi_linux.o`;
2. compiles the test and `lib/sys/grail_ffi.grl` for x86-64 with the FFI compiler;
3. verifies the single `// grail-link: grail_ffi_linux.o` note and unmangled C calls;
4. assembles with clang, links with `-nostartfiles -no-pie ... -lc -lpthread -ldl
   -Wl,-e,_start`, and runs in a scratch directory;
5. compiles the same sources to AArch64 and RISC-V 64 assembly and checks the link note and
   C calls (assembly/static only; no cross C backend link or execution).

The runner requires `GRAIL_FFI_COMPILER`. The current compiler in this branch has no
`extern "C"` support, so using `GRAIL_COMPILER` only works once the FFI lane merges.

The test-only runtime copy removes `raw_tp_set` from `rt_thread_init` so the host C
library's thread pointer/TLS remains valid. The Grail worker record is still initialized.
This is a **harness patch**, not a runtime change: the shipping runtime and the freestanding
backend need a proper libc/entry integration or a freestanding C backend before this layer
can be installed.

## Verification and limits

Executed: x86-64 Linux. The test creates `ffi_note.txt`, writes `hello ffi`, reads it back,
checks `file_stat` size/layout, checks monotonic and wall clocks, and sets/gets
`GRAIL_FFI_TEST=ok`.

Not claimed:

- no Windows or macOS execution (the C backends there are static-only);
- no cross C backend link/execution for AArch64/RISC-V 64, only Grail assembly checks;
- no dynamic library, socket, process or thread wrappers in this module yet;
- no automatic handle destruction, no `CStr` paths, no error-detail accessor;
- no installed stdlib integration and no FFI compiler in this branch;
- the current `grail build`/`grail run` CLI link path does not yet consume
  `// grail-link:` inputs (the FFI/test tooling does), so the executed test uses
  `tools/test-ffi-runtime.mjs` directly until that lands;
- no production runtime initialization: the adapter's empty environment and malloc
  allocator are test scaffolding.
