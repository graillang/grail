# First Grail-facing wrappers over the C OS ABI

2026-11-08. Status: **implemented and executed on Linux x86-64**. This is the first
Grail-facing standard-library layer over `include/grail/`, using the merged v3 C FFI
(`extern "C"`, byte views, `CStr`, opaque handles, C-layout records and `T |? Error`). The
compiler, `runtime.grl` and `os-linux.grl` come from current `main`; nothing here changes
compiler sources.

## Location and loading

`lib/sys/grail_ffi.grl` is module `sys_grail`. It deliberately sits in a subdirectory: the
current standard-library loader auto-includes only top-level `lib/*.grl`, so adding this
module does not affect existing programs. Pass it explicitly until the stdlib/install layout
includes subdirectories.

The module declares one deduplicated link input, `grail_ffi_linux.o`. The object is
**generated by the test/build script**, not committed: it combines the Linux reference backend
and `runtime/abi/ffi/grail_ffi_shim.c`. The runner builds it under `lib/sys/` and links that
path explicitly; bare link inputs are currently resolved by `tools/native.mjs` relative to the
entry directory, and `grail build`/`run` does not consume link notes, so this is not yet an
installable package. See `.gitignore`.

## Surface

```grl
pub const OPEN_READ: u64 = 1;
pub const OPEN_WRITE: u64 = 2;
pub const OPEN_CREATE: u64 = 4;
pub const OPEN_TRUNCATE: u64 = 8;
pub const OPEN_APPEND: u64 = 16;
pub const OPEN_EXCLUSIVE: u64 = 32;
pub const CLOCK_MONOTONIC: u64 = 0;
pub const CLOCK_REALTIME: u64 = 1;
pub const ABI_VERSION: u64 = 4294967296;
pub const ADDRESS_INET: u64 = 1;
pub const SOCKET_STREAM: u64 = 1;
pub const SHUTDOWN_READ: u64 = 1;
pub const SHUTDOWN_WRITE: u64 = 2;
pub const SHUTDOWN_BOTH: u64 = 3;
pub const ERROR_INVALID_ARGUMENT: i64 = -1;
pub const PROCESS_EXITED: u64 = 0;
pub const PROCESS_SIGNALED: u64 = 1;
pub const PROCESS_STILL_ACTIVE: u64 = 2;

handle File;
handle Socket;
handle Process;
handle Thread;

pub enum Error { Status(i64) }

pub fn init() -> unit |? Error;
pub fn shutdown() -> unit |? Error;
pub fn open(path: &[u8], flags: u64, mode: u64) -> File |? Error;
pub fn read(file: File, buffer: &mut [u8]) -> u64 |? Error;
pub fn read_bytes(file: File, capacity: u64) -> u8[] |? Error;
pub fn write(file: File, data: &[u8]) -> u64 |? Error;
pub fn close(file: File) -> unit |? Error;
pub fn stat(file: File) -> FileStat |? Error;
pub fn size(file: File) -> u64 |? Error;
pub fn now(clock: u64) -> i64 |? Error;
pub fn monotonic() -> i64 |? Error;

pub fn env_get_bytes(name: &[u8], capacity: u64) -> u8[] |? Error;
pub fn env_set(name: &[u8], value: &[u8]) -> unit |? Error;

pub fn loopback(port: u64) -> Address;
pub fn tcp() -> Socket |? Error;

pub fn listen(socket: Socket, backlog: u64) -> unit |? Error;

pub fn send(socket: Socket, data: &[u8]) -> u64 |? Error;

pub fn socket_close(socket: Socket) -> unit |? Error;
pub fn local_address(socket: Socket) -> Address |? Error;

pub fn local_port(socket: Socket) -> u64 |? Error;

pub fn thread_detach(thread: Thread) -> unit |? Error;
```

`Address` mirrors the C record: five 64-bit fields (`struct_size`, `abi_version`, `family`,
`port`, `scope_id`) followed by sixteen `u8` bytes, 56 bytes total. `loopback` is the only
constructor; `bind` and `connect` reject any address that is not IPv4 127.0.0.1 with
`ERROR_INVALID_ARGUMENT` before calling C. The record is public because `local_address` and
`peer_address` return it, but no non-loopback TCP path is exposed.

`ProcessStatus` mirrors the C record: `struct_size`, `abi_version`, `kind`, `exit_code`,
`term_signal` (five 64-bit fields, 40 bytes). `kind` is `PROCESS_EXITED`,
`PROCESS_SIGNALED` or `PROCESS_STILL_ACTIVE`; `exit_code`/`term_signal` are valid for the
matching kind.

`FileStat` mirrors the C record exactly: `struct_size`, `abi_version`, `kind`, `flags`,
`size`, `mode`, `link_count`, `device`, `inode`, `modified_ns`, `accessed_ns`,
`created_ns` (twelve 64-bit fields, 96 bytes). The executed test checks
`struct_size == 96`, `abi_version == GRAIL_ABI_VERSION`, and `kind == FILE` so a layout
regression fails at runtime as well as at C compile time.

## Exact boundary rules

- **Paths and data** cross as `&[u8]`/`&mut [u8]` pairs `(pointer, length)`. The pointer is
  the view's own storage; there is no copy, no NUL terminator requirement and no
  `CStr` in this surface. C may read/write the bytes only for the duration of the call and
  must not retain the pointer.
- **Buffers are call-scoped loans.** `read`/`env_get` write at most the view's capacity and
  return the actual/required length. A returned length greater than the buffer capacity is
  a short read/query, not an error; `read_bytes`/`env_get_bytes` allocate a Grail-owned
  vector and copy exactly the returned prefix.
- **Short I/O is legal.** `write`/`send` return the number of bytes written (0 or less than
  the input is valid); callers that need a full write must loop. `read`/`recv` returning 0 is
  clean EOF. `recv_bytes` allocates a Grail-owned vector and copies the actual prefix.
- **`File`, `Socket`, `Process` and `Thread` are C-owned opaque handles.** Grail never
  constructs, inspects, sizes, borrows or frees them. Treat them as affine by convention:
  call `close`/`socket_close`/`process_close`, or `thread_join`/`thread_detach`, exactly once;
  never use a handle after close/join/detach or consume it twice. The compiler's handles are
  not linear in this increment, so the convention is not machine-checked. `tcp`/`accept` return
  new socket handles; `spawn`/`thread_spawn` return new process/thread handles.
  `socket_shutdown` does not close. `wait` does not consume a process handle; `process_close`
  does. Closing a still-running child leaves it unreachable and unreaped.
- **No C-owned pointer is returned.** `open` returns a handle; `stat`/`time` fill
  Grail-owned out-records; byte results are copied into Grail-owned vectors. C never hands
  back a `u8[]`/view or a pointer Grail would drop.
- **Out-records are Grail-owned.** `LengthOut`, `TimeOut` and `FileStat` are constructed by
  Grail, passed as the C record address, written by C during the call, and freed by Grail's
  normal record drop. C must not retain or free them.
- **Errors are negative statuses.** `grail_status`/`grail_result` values cross as `i64`;
  the wrapper maps negative values to `Error::Status(code)`. No `errno` is read, cleared or
  synthesized at the boundary. `Error::is_transient` recognizes `WOULD_BLOCK`,
  `INTERRUPTED`, `TIMED_OUT` and `BUSY`; a caller that needs raw OS detail can later call the
  ABI's `grail_os_error_last` through another declaration.
- **Initialization is explicit.** `init()` must run before any file/time/env/socket call and
  `shutdown()` after all handles are closed. `grail_ffi_init` supplies a malloc/free
  allocator and an empty startup environment; the real Grail entry shim must supply the
  runtime allocator and UTF-8 argv/environment blocks when this surface is integrated.
- **The handle-return adapter is thread-local and immediate.** The C ABI writes a handle
  through an out-pointer, which the current scalar/handle FFI cannot express. The test shim
  stores it in a thread-local slot; `open`, `tcp`, `accept`, `spawn` and `thread_spawn` read
  that slot immediately. No other handle-producing call may intervene on the same thread, and
  the adapter is not part of the stable ABI.
- **Process arguments are a NUL-separated blob.** `spawn(program, arguments)` treats
  `arguments` as argv[1..] and the shim builds the full offset-addressed argv with `program`
  as argv[0]; an empty blob relies on the ABI's argv[0] insertion. The child inherits stdio
  and the runtime environment and uses the inherited working directory. No shell, custom
  environment, cwd, `terminate` or `kill` wrapper is exposed.
- **Thread entries are C-ABI function pointers.** `thread_spawn(entry, user)` passes a
  `cfn(u64) -> u64` and a user word. `thread_join` blocks, consumes the handle and returns the
  callback result; `thread_detach` consumes it without a result. The callback runs on a native
  thread without Grail task/TLS bootstrap, so it must remain self-contained: no allocation,
  printing, panic or runtime service until the runtime thread bootstrap is integrated.
- **Sockets are blocking.** `accept`, `connect`, `send` and `recv` have no timeout or
  non-blocking flag in this surface. `socket_shutdown` is explicit and separate from
  `socket_close`. Only TCP/IPv4 loopback is exposed; UDP, `send_to`/`recv_from`, DNS and
  non-loopback addresses are deferred.

## Build and execution

`tools/test-ffi-runtime.mjs`:

1. compiles the Linux reference backend and the FFI shim into
   `lib/sys/grail_ffi_linux.o`;
2. compiles the file, socket and process/thread tests plus `lib/sys/grail_ffi.grl` for x86-64
   with the FFI compiler;
3. verifies the single `// grail-link: grail_ffi_linux.o` note and unmangled C calls;
4. assembles with clang, links with `-nostartfiles -no-pie ... -lc -lpthread -ldl
   -Wl,-e,_start`, and runs in a scratch directory;
5. compiles the same sources to AArch64 and RISC-V 64 assembly and checks the link note and
   C calls (assembly/static only; no cross C backend link or execution).

The runner uses `GRAIL_FFI_COMPILER` or `GRAIL_COMPILER`; both should point at a compiler
built from current `main`, which includes the v3 FFI. It compiles with `runtime.grl` and
`os-linux.grl` from this tree.

The tests run on the unmodified runtime: `rt_thread_init` installs Grail's worker record as
the thread pointer, and the compiler's host-TLS bridge (see `docs/ffi.md`) switches to the C
library's TLS for every foreign call and back to Grail's for exported callbacks.

## Verification and limits

Executed: x86-64 Linux. The file test creates `ffi_note.txt`, writes `hello ffi`, reads it
back, checks `file_stat` size/layout, checks monotonic and wall clocks, and sets/gets
`GRAIL_FFI_TEST=ok`. The socket test creates a listener on `127.0.0.1:0`, binds and listens,
reads the ephemeral port back, checks `struct_size == 56`/`abi_version`, connects a second
socket, accepts, sends/receives `ping` and `pong`, checks the peer address and port, shuts
down and closes all three sockets, and verifies that a non-loopback bind is rejected with
`ERROR_INVALID_ARGUMENT` (`-1`).

Not claimed:

- no Windows or macOS execution of these wrappers (the separate C ABI Wine harness executes
  the Windows metadata/reparse/DNS paths);
- no cross C backend link/execution for AArch64/RISC-V 64, only Grail assembly checks for the
  file, socket and process/thread tests;
- no dynamic library wrappers, process environment/cwd/terminate/kill, thread naming/stack
  options, mutexes or condition variables;
- no automatic handle destruction, no `CStr` paths, no error-detail accessor;
- no installed stdlib integration;
- the current `grail build`/`grail run` CLI link path does not yet consume
  `// grail-link:` inputs (the FFI/test tooling does), so the executed test uses
  `tools/test-ffi-runtime.mjs` directly until that lands;
- no production runtime initialization: the adapter's empty environment and malloc
  allocator are test scaffolding.
